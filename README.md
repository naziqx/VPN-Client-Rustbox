# RustBox

VPN-клиент для компа, написанный на Rust. Похож на NekoBox и Happ: кидаешь ссылку или подписку,
выбираешь сервер, жмёшь «Подключить» — и всё. Внутри работают sing-box и Xray.

Нормально работает на **Linux** (сам пользуюсь на Arch). Под **Windows** код уже есть,
но на живой винде ещё не гонял — подробнее [ниже](#windows).

![Главное окно](docs/screenshots/main-dark.png)

## Что умеет

- Понимает почти все ссылки: `vless://` (Reality, Vision, gRPC, WS, XHTTP), `vmess://`, `trojan://`,
  `ss://`, `hysteria2://`, `tuic://`, `socks://`.
- Подписки любых форматов, включая те, что делают для Happ (про них отдельно ниже).
  Показывает, сколько трафика потрачено и когда подписка кончается.
- Два ядра на выбор — sing-box и Xray. Если одно не тянет какой-то сервер, клиент сам переключится на другое.
- Проверка серверов: URL-тест (реально гоняет запрос через сервер) или TCP ping (быстро, но только смотрит, открыт ли порт).
- Тёмная и светлая тема. Есть версия для командной строки.

Режимы работы:

| Режим | Что пойдёт через VPN |
|---|---|
| **Прокси** | только то, что сам настроишь на `127.0.0.1:2080` |
| **Системный прокси** | браузеры и почти все программы, без лишних настроек |
| **TUN** | вообще всё: игры, мессенджеры, программы, которые про прокси не знают |

### Фишка с подписками от Happ

Многие VPN-сервисы отдают Happ не просто ссылки, а целые конфиги. «Авто»-серверы в них — это
несколько серверов сразу, и Xray сам выбирает живой. А вот другим клиентам тот же сервер
приходит одной ссылкой, и часто это как раз запасной сервер, который не работает.
Отсюда классика: «в Happ всё летает, а в моём клиенте ошибка».

RustBox просит у сервиса такие же конфиги, как Happ, и запускает их целиком — «Авто» работает как надо.
Заодно чинит косяк в самих конфигах: там DNS часто уходит в мёртвый сервер, и обычные сайты
(Яндекс, банки) грузятся по 10 секунд. Если сервис вернёт что-то непонятное, клиент просто возьмёт
обычные ссылки.

## Установка

### Linux (Arch)

Сначала ставим ядра:

```sh
sudo pacman -S sing-box xray v2ray-geoip v2ray-domain-list-community
```

Потом качаем архив из [Releases](../../releases), распаковываем и запускаем `rustbox`.
Или собираем сам (см. [Сборка](#сборка)).

Готовая сборка сделана на свежем Arch и хочет glibc 2.44+. На Ubuntu/Debian проще собрать из исходников.

Для режима TUN sing-box нужны права на создание сетевого интерфейса. Клиент сам предложит их выдать
(спросит пароль), либо можно руками:

```sh
sudo setcap cap_net_admin,cap_net_bind_service=+ep /usr/bin/sing-box
```

Системный прокси умеет включаться в GNOME и KDE.

### Windows

Будет архив `RustBox-windows.zip`, где уже лежит всё нужное: сам клиент, ядра и базы geoip/geosite.
Распаковал — запустил `rustbox.exe`, устанавливать ничего не надо.

- Винда может ругнуться, что программа неизвестная (она не подписана). Жми «Подробнее» → «Выполнить в любом случае».
- Для режима TUN запускай от имени администратора (правый клик по `rustbox.exe`).
- Когда выключаешь системный прокси, клиент возвращает те настройки, что были до него.

> На настоящей винде это пока не проверялось. Если что-то сломалось — заведи issue и приложи лог
> (кнопка «Лог» внизу окна).

## Как пользоваться

1. Скопируй ссылку на подписку или сервер.
2. В клиенте нажми **Ctrl+V** (или «+ Добавить» → «Добавить подписку…»).
3. Выбери сервер. Можно сначала нажать «Проверить», чтобы увидеть, какие живые.
4. Выбери режим и жми **«Подключить»**. Ещё можно дважды кликнуть по серверу или нажать Enter.

Горячие клавиши: Ctrl+V — вставить, Enter — подключиться, Del — удалить, Ctrl+A — выделить всё.

## Командная строка

Всё то же самое можно делать из терминала:

```sh
rustbox-cli import 'vless://…' 'ss://…'      # ссылки, файл или "-" для stdin
rustbox-cli sub add "Мой VPN" https://…/sub   # добавить подписку
rustbox-cli sub update                         # обновить подписки
rustbox-cli list                               # список серверов
rustbox-cli core xray                          # выбрать ядро
rustbox-cli ping --url                         # проверить серверы
rustbox-cli run 5 --system-proxy               # подключиться (Ctrl+C — отключиться)
rustbox-cli config 5                           # посмотреть, какой конфиг уйдёт в ядро
```

## Где лежат настройки

| | Linux | Windows |
|---|---|---|
| Настройки | `~/.config/rustbox/settings.json` | `%APPDATA%\rustbox\settings.json` |
| Серверы и подписки | `~/.local/share/rustbox/profiles.json` | `%APPDATA%\rustbox\profiles.json` |
| Временные конфиги ядер | `$XDG_RUNTIME_DIR/rustbox/` | `%TEMP%\rustbox\` |

## Сборка

Нужен Rust 1.85 или новее.

```sh
cargo build --release
./target/release/rustbox          # окно
./target/release/rustbox-cli --help
```

Собрать версию для Windows прямо из Linux (получится `dist/RustBox-windows.zip` вместе с ядрами):

```sh
sudo pacman -S mingw-w64-gcc
scripts/package-windows.sh
```

## Как устроен код

```
crates/
  platform/  всё, что зависит от системы
             ├─ linux.rs        прокси в GNOME/KDE, права для TUN, поиск ядер
             ├─ windows.rs      прокси через реестр, TUN от администратора
             └─ unsupported.rs  заглушка для остальных систем
  core/      основная логика, не знает ни про систему, ни про окно
             ├─ model.rs        серверы, протоколы, группы
             ├─ link/           разбор и сборка ссылок
             ├─ subscription.rs загрузка подписок
             ├─ xray_json.rs    конфиги в формате Happ
             ├─ config/         конфиги для sing-box и Xray
             ├─ process.rs      запуск и остановка ядер
             ├─ latency.rs      проверка серверов
             ├─ connection.rs   подключение целиком
             └─ storage.rs, settings.rs, tls_pin.rs
  cli/       rustbox-cli
  gui/       окно на egui: app.rs — состояние, view.rs — главный экран,
             dialogs.rs — диалоги, theme.rs — оформление, tasks.rs — фоновые задачи
```

Хочешь добавить новую систему — пиши модуль в `crates/platform`. Новое ядро — в `core/src/config/`.
Остальной код трогать не придётся.

## Тесты

```sh
cargo test --workspace
```
